# persona: dev-docs

_Drafted from observation 2026-10-31. Native-lens critic pass:
2026-10-31, gauntlet loop 6 — machine ears, not the owner's.
Corrections welcome via issue or PR._

## Who

Indonesian software developer. Reads documentation and READMEs daily —
mostly in English, sometimes in Indonesian, and instantly notices when an
Indonesian doc was translated rather than written. Uses libraries whose
 Indonesian docs read like machine output; has learned to prefer the
English page and resents having to.

## How they read

- Scans first: headings, code blocks, lists. Prose only when stuck.
- Reads Indonesian docs at full speed when they're good — and stops
  cold at the first sentence that parses wrong.
- The pause-trigger is one thought: "ini terjemahan." After it fires,
  every awkward line gets blamed on the translation, fair or not.

## Vocabulary & register

- Semi-formal santai; "kamu" or impersonal, consistent either way.
- Technical vocabulary stays English ( deploy, cache, dependency) —
  translating those reads amateur. "Anda" in a dev doc reads like a
  bank letter.

## What earns trust

- Code-adjacent precision: numbers, flags, file paths verbatim.
- Sentences that were clearly written by someone who does the thing.
- Punctuation that behaves: periods, not academic semicolon chains.

## What kills it in 2 seconds

- Passive-chain sentences where the agent of every verb is unclear.
- Calques: "melakukan implementasi terhadap", "dalam konteks di mana".
- Steps whose Indonesian is grammatical but whose *instructions* got
  lost — the translation changed what to type.

## What makes them act

Follows the setup guide end-to-end without opening the English page,
and links the Indonesian doc to their team. A doc that survives this
reader's first scroll is a doc that was written, not translated.
